# 10 · Auditoría de DevOps (Fase 1, solo lectura)

> 04/11/2026 · rama `auto/auditoria-integral`. Fuentes: `.github/workflows/*` (6), `vercel.json`, `next.config.ts`, `package.json`, `.env.example`, `src/config/env.ts`, un grep de `process.env`, `gh run list`, `gh variable list` y `gh secret list` (solo nombres), y la base en línea en modo de solo lectura. No se cambió nada.

## 1. Diagnóstico inicial

Las bases están bien puestas: CI obligatoria (lint, tipos, unitarias, fronteras y 200 pruebas de base), `GITHUB_TOKEN` con `contents: read` en todos los workflows, versiones de npm fijadas, cabeceras de seguridad y CSP con nonce, salud con monitor, y copia diaria cifrada que funciona. El punto débil es que **la mitad de la tubería existe solo en papel**: `deploy` y `e2e` se saltan en cada push porque faltan los secretos, y producción se publica desde `feat/app-mvp` contra la misma base que las pruebas. No hay P0. Hay un P1 (entornos) y varios P2 de despliegue, rollback y registros.

| CI | `ci.yml`: `npm ci`, `npm run check` (lint, typecheck, Vitest, fronteras) y `test:db`. Última corrida correcta el 04/11. Localmente, `npm run test:db` da 200/200 |

## 4. No verificado

- Las variables de entorno configuradas en Vercel (si `SENTRY_DSN`, las VAPID y `CRON_SECRET` están en *Production*) y el tiempo real de retención de los registros: hace falta el panel de Vercel.
- Que `deploy.yml` funcione: nunca se ejecutó.
- `npm run build` y `npm run test:e2e`: no se ejecutaron, para ahorrar créditos; la CI cubre el build solo dentro de E2E, que está apagado.
- Que `db:types` produzca los mismos tipos con la CLI v3 (comando remoto, no se ejecutó).

## 5. Puntuación: 3/5

La seguridad de la tubería (permisos, secretos, cifrado, auditorías automáticas) es buena, y la CI protege cada cambio. Bajan la nota que producción y pruebas comparten base (OPS-01), que el despliegue y las E2E nunca corren en GitHub (OPS-02 y OPS-03), que publicar depende de un push manual a otra rama (OPS-04) y que, si algo falla en la demo, no hay vuelta atrás de los archivos ni registro persistente de errores (OPS-05 y OPS-06). Casi todo se arregla con configuración y cuentas, no con código.
